# B4 实时功能 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供 `GET /api/v1/ws`，把小屋的成员变化、presence（在线 / 离线）和 `pet.tap` 实时推给同屋成员；Redis 故障时单节点照常工作。

**Architecture:** service 层新增四块：`Hub`（本机连接表、订阅、投递规则，只通过 `Conn` 接口操作连接）、`PresenceService`（上下线判定与广播）、`EventPublisher`（实现现有 `Publisher`：取 seq、发 Redis、失败时本机投递）、`RealtimeService`（快照与 `pet.tap`）。Redis 侧的 seq / Pub/Sub / presence ZSET 放在 `internal/platform/realtime`，service 只依赖接口。`internal/handler/ws_handler.go` 负责升级、读写协程和帧解析。

**Tech Stack:** Go、Gin、pgx、go-redis v9、新依赖 `github.com/coder/websocket`（TRD 选定）。无新迁移。

**Spec:** `docs/superpowers/specs/2026-11-17-b4-realtime-design.md`；协议以后端 TRD v1.4 第 9 章为准，7.3、7.8、11、12.2 为补充。

## Global Constraints

- 路径 `GET /api/v1/ws`；升级前 `middleware.Auth` 失败 401，未 onboarding 403 `ONBOARDING_REQUIRED`（普通 JSON 错误响应，不升级）
- 帧 `{t, id?, seq?, d}`；服务端帧不带 `id`；`error` 帧 `d={ref, code}`，`code` 只用 `ROOM_NOT_FOUND`、`VALIDATION_FAILED`
- 只有 `member.joined`、`member.left` 带 seq（Redis 正常时）；`room.kicked`、`code.invalidated`、`presence.update`、`pet.action`、`resync`、`server.restart`、`hello` 一律不带
- 协议常量（代码常量，测试可通过 `RealtimeConfig` 覆盖）：心跳 25s、ping 超时 10s、presence 70s、每用户本节点 3 条连接、每连接最多订阅 2 个房间、读帧 4096 字节、每连接每秒 10 帧、发送队列 64、写超时 5s、`pet.tap` 每连接每秒 2 次、`proto=1`
- 关闭码：1001 服务重启、1008 刷帧、1009 超长帧、4001 被新连接替换
- Redis 键：`room:{rid}:seq`（INCR）、`presence:u:{uid}`（ZSET，成员连接 id、分数过期时间的 Unix 毫秒，键 TTL 70s）、频道 `ws:events`；B4 不写 `room:{rid}:events`
- 新环境变量 `MIN_APP_VERSION`，默认 `0.0.0`
- 事件只在提交后发布（已有约定）；service 不依赖 Gin 与 WebSocket 库
- 日志不得出现 token；兜底日志 30 秒限频
- 每个任务测试通过后，按任务给出的提交信息提交并推送 `jinheng main`；数据库测试用 `dbtest.Reset(t)`，Redis 测试沿用 `ratelimit/redis_test.go` 的 `newTestRedis` 跳过约定

## Review Focus

1. **被劫持连接上的 `ReadTimeout`**：`http.Server.ReadTimeout=15s` 的读截止时间在 hijack 后仍然生效，空闲超过 15 秒的 WS 会被断开。期望：空闲连接一直保持（Task 6 测试 `TestWS_IdleConnSurvivesReadTimeout`）
2. **网络断开但没有正常关闭**：客户端直接消失。期望：ping 超时后连接关闭，同屋的人收到 `offline`（Task 6 测试 `TestWS_DeadClientGoesOffline`）
3. **同一用户两台设备，一台关闭**：期望仍为在线，不广播 `offline`；两台都关才广播（Task 4 测试 `TestPresence_SecondConnKeepsOnline`）
4. **乱帧**：非 JSON、二进制帧、`d` 类型不对、未知 `t`、超过 4KB、1 秒内 11 帧。期望：前四种回 `error VALIDATION_FAILED` 且连接保持，后两种按 1009 / 1008 关闭，任何情况都不 panic（Task 6 测试 `TestWS_MalformedFrames`）
5. **Redis 中途恢复**：停 Redis 期间事件不带 seq 照常送达；Redis 订阅重连后本机所有连接收到 `resync`（Task 2 测试 `TestBus_ReconnectCallback`、Task 4 测试 `TestPublisher_ResyncOnReconnect`）

### Task 3: Hub

**Files:**
- Create: `internal/service/realtime_ports.go`、`internal/service/hub_service.go`
- Test: `internal/service/hub_service_test.go`

**Interfaces:**
- Consumes：Task 1 的 `model.Frame`、`Event.Kind`
- Produces（`realtime_ports.go`）：
  - `type Conn interface { ID() string; UserID() string; Send(f model.Frame) bool; Close(code int, reason string) }`（`Send` 非阻塞，队列满返回 false）
  - `type RealtimeConfig struct { Heartbeat, PingTimeout, PresenceTTL, WriteTimeout time.Duration; MaxConnsPerUser, MaxSubsPerConn, ReadLimit, FramesPerSec, SendQueue, TapsPerSec int; MinAppVersion string }`，`func DefaultRealtimeConfig(minAppVersion string) RealtimeConfig` 返回 Global Constraints 的值
  - `type Bus interface { NextSeq(ctx, roomID string) (int64, error); CurrentSeq(ctx, roomID string) (int64, error); Publish(ctx context.Context, payload []byte) error; Run(ctx context.Context, onMessage func([]byte), onReconnect func()) }`
  - `type PresenceStore interface { Add(ctx, userID, connID string, now time.Time) error; Remove(ctx, userID, connID string) error; Count(ctx, userID string, now time.Time) (int, error) }`
- Produces（`hub_service.go`）：
  - `func NewHub(cfg RealtimeConfig) *Hub`
  - `Register(c Conn)`：本节点该用户连接数超过 `MaxConnsPerUser` 时，对最早注册的那条调用 `Close(4001, "replaced")` 并注销
  - `Unregister(c Conn)`
  - `BeginSub(c Conn, roomID string) error`：超过 `MaxSubsPerConn` 返回 `ErrTooManySubs`；之后该房间的投递进入该连接的暂存区
  - `EndSub(c Conn, roomID string, snap model.RoomSnapshot)`：先 `Send(Frame{T:"room.snapshot", D:snap})`，再按到达顺序发暂存的帧，丢弃 `Seq != 0 && Seq <= snap.Seq` 的帧，之后转为正常投递
  - `CancelSub(c Conn, roomID string)`、`Unsub(c Conn, roomID string)`
  - `Subscribed(c Conn, roomID string) bool`
  - `Deliver(e Event, seq int64)`：`KindState` / `KindTransient` 只投给 `To` 中、且已订阅（或正在订阅）`e.RoomID` 的连接；`KindPersonal` 投给 `To` 中用户的全部连接；`room.kicked` 投递后取消该用户所有连接对 `e.RoomID` 的订阅；`Send` 返回 false 的连接立刻 `Close(1008, "slow consumer")` 并注销
  - `Broadcast(f model.Frame)`：发给本机全部连接
  - `LocalCount(userID string) int`
  - `Shutdown()`：对全部连接发 `server.restart`，再 `Close(1001, "restart")`
  - 错误 `ErrTooManySubs`

  - `TestHub_FourthConnEvictsOldest`：同一用户注册 4 条 → 第 1 条收到 `Close(4001, …)`，`LocalCount==3`
  - `TestHub_SlowConsumerClosed`：`Send` 返回 false → 该连接 `Close(1008, …)`，其他连接照常收到
  - `TestHub_SnapshotThenBuffered`：`BeginSub` 后投递 seq 3、seq 5、无 seq 的 `presence.update`；`EndSub(snap.Seq=4)` → 收到顺序为 `room.snapshot`、seq 5、`presence.update`（seq 3 被丢弃）

行为要点（实现者据此写代码）：
- 升级前：未 onboarding → `Fail(403, ONBOARDING_REQUIRED)`；调用 `http.NewResponseController(w).SetReadDeadline(time.Time{})` 清除 `ReadTimeout` 留下的截止时间，再 `websocket.Accept`；`conn.SetReadLimit(cfg.ReadLimit)`
